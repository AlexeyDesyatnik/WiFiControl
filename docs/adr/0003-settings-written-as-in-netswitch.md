# Настройки IPv4 и прокси записываются так же, как в NetSwitch

Способы записи настроек переносим из NetSwitch вместе с кодом и не переизобретаем:

- Настройки IPv4 — штатным `netsh.exe`, скрытым процессом; успех шага определяется не кодом возврата, а тем, что после команд прочитано с адаптера (ADR 0002 NetSwitch).
- Возврат к DHCP на адаптере без соединения — удаление ручных адресов через netsh и включение DHCP в постоянных настройках через `MSFT_NetIPInterface` (ADR 0003 NetSwitch).
- Системный прокси — запись в раздел реестра пользователя, включая оба значения в `Connections`, и уведомление программ через `InternetSetOption`.
- WinHTTP-прокси — `WinHttpSetDefaultProxyConfiguration` с копией для 32-разрядных программ.

Причина — всё это проверено на живых машинах, а в WiFiControl запись без соединения становится основным сценарием, а не редким: настройки IPv4 выставляются на отключённом Wi-Fi-адаптере ([ADR 0004](0004-ipv4-before-connect.md)).

## Considered Options

- **Целиком WMI (`MSFT_NetIPAddress`, `MSFT_NetIPInterface`, как `New-NetIPAddress`)** — без дочерних процессов, и класс доступен на всех поддерживаемых версиях, но поведение без соединения пришлось бы проверять заново. Можно вернуться к этому отдельным решением после разведки.

## Consequences

- Путь проверен на Windows 11 26H2 на отключённом Wi-Fi-адаптере ([проверка записи](../write-check.md), 2026-10-26, четыре полных прогона и три варианта), и он ведёт себя так же, как в NetSwitch на Windows 10 21H2:
  - netsh `set address source=static` на отключённом адаптере записывает ручные настройки и ставит `DisableDhcpOnConnect = 1`; DHCP выключается при подключении.
  - Если статика была действующей (адаптер работал с ней, затем отключён), обычный netsh `source=dhcp` возвращает DHCP.
  - Если статика только записана и подключения не было, обычный netsh отказывает с «DHCP is already enabled» (код 1); запасной путь — `delete address … gateway=all` и `MSFT_NetIPInterface` в постоянном хранилище — возвращает DHCP, и после подключения адрес приходит по DHCP.
  - Запись статики на подключённом адаптере работает: адрес действует через ~3,5 с, маршрут по умолчанию на месте.
- Сама запись верна, но первое подключение после неё может потерять маршрут по умолчанию — это касается порядка переключения, см. [ADR 0004](0004-ipv4-before-connect.md).
- Применение записывает только прокси, заданный вручную: автоопределение и сценарий настройки (PAC) в системном прокси при этом выключаются. Поддержка PAC — в идеях на будущее.
- Ограничения net40 при переносе снимаются: async вместо блокирующих ожиданий, `System.Text.Json` вместо `JavaScriptSerializer`.
