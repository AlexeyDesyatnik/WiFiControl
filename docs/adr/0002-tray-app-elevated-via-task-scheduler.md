# Одна программа в трее с правами администратора, запуск задачей Планировщика

Инструмент — один процесс в сеансе пользователя: окно, значок в трее, наблюдатель и запись настроек. Права администратора он получает от задачи автозапуска — задачи Планировщика «при входе в систему, с наивысшими правами», которую создаёт сам по команде «Запускать при входе». Запрос UAC при каждом входе не нужен, а наблюдатель работает с первой минуты после входа, в том числе когда Windows сама подключилась к сети.

Доводы за один процесс в сеансе пользователя:

- Доступ к местоположению в Windows 11 24H2+ выдаётся пользователю. Процесс в его сеансе получает его так же, как любое классическое приложение; как поведёт себя служба под LocalSystem — неизвестно.
- Системный прокси — настройка пользователя, а уведомить запущенные программы о его смене (`InternetSetOption`) можно только из его сеанса.
- Один процесс проще отлаживать и проще переносить: ни установщика службы, ни канала между процессами.

Ядро (модель, применение, Wi-Fi) держим отдельной библиотекой за интерфейсами, не зависящей от интерфейса, — чтобы при необходимости перенести запись настроек в службу, не переписывая её.

## Considered Options

- **Служба + интерфейс без прав администратора** — правильнее по безопасности и без повышения прав вовсе, но нужны установщик, именованный канал и запись прокси в чужой раздел реестра; доступ службы к Wi-Fi при ограничениях 24H2 не проверен.
- **Запрос UAC при каждом запуске** (как NetSwitch) — после перезагрузки наблюдатель не работает, пока человек не запустит программу и не подтвердит права.
- **Скрипт на событие 8001 журнала WLAN-AutoConfig** через Планировщик — минимум кода, но нет собственного выбора сети, ради которого всё затевается.

## Consequences

- Процесс с правами администратора постоянно работает в фоне.
- Учётная запись пользователя должна входить в группу администраторов: иначе «наивысшие права» у задачи ничего не дадут.
- Ручной запуск exe по-прежнему запрашивает UAC. Второй экземпляр не запускается, а показывает окно уже работающего.
- Работает ли доступ к местоположению под задачей Планировщика так же, как при ручном запуске, проверяет [разведочная сборка](../recon.md). По прогону 2026-10-26 на Windows 11 26H2 — да: задача «при входе, с наивысшими правами» открывает окно без UAC, процесс работает от имени пользователя, и WLAN API отвечает так же, как при ручном запуске. Разрешение записывается в разделе пользователя (`HKCU\…\ConsentStore\location\NonPackaged`), что подтверждает довод о процессе в его сеансе. На Windows 10 запуск из Планировщика не проверен.
- Если доступ к местоположению выключен, инструмент не получает ни имени текущей сети, ни списка сетей, ни уведомлений WLAN (отказ с кодом 5), хотя профили сетей Windows читаются. Это состояние нужно распознавать по коду ошибки и показывать человеку с подсказкой, где включить доступ.
