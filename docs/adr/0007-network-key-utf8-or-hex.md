# Сеть узнаётся по строковому ключу: текст UTF-8 или `hex:` с байтами

Имя сети (SSID) в Wi-Fi — до 32 байт без заданной кодировки. В привязках и в `WiFiControl.json` сеть хранится строковым ключом: если байты имени — корректный UTF-8, ключ — сам текст (`Office`); если нет — шестнадцатеричная запись байтов с меткой (`hex:CFF0E8E2E5F2`), и так же имя показывается в окне. Сравнение ключей точное, с учётом регистра.

Почему так:

- Почти все современные роутеры и телефоны кодируют имя в UTF-8, и для них ключ остаётся обычным текстом: файл читается и правится руками, как в NetSwitch.
- Старые роутеры встречаются с именами в cp1251 или GBK. Если читать такие байты как UTF-8, неверные байты превращаются в `�`: две разные сети склеиваются в одну привязку, а в окне — мусор. Запись байтов с меткой этого не допускает.
- Поддержка почти ничего не стоит: ключ всё равно строка, нужна одна функция «байты → ключ» при чтении Wi-Fi. Само подключение ключ не затрагивает — Windows подключается по байтам из сканирования и из профиля сети Windows.

## Considered Options

- **Только UTF-8, остальное не поддерживать** — проще на одну функцию, но молча склеивает разные сети и показывает искажённые имена.
- **Ключ — всегда байты (hex или base64)** — однозначно, но файл перестаёт быть читаемым для обычных имён, а ради редкого случая страдает частый.

## Consequences

- Ключ меняется, только если меняются байты имени: роутер, переименованный в ту же строку другой кодировкой, станет новой сетью.
- Имя, которое человек вводит руками (привязка для сети, которой сейчас нет), — текст; ключ `hex:` получается только из прочитанных у Windows байтов.
