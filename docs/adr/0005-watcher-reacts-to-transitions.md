# Наблюдатель реагирует на смену сети, а не удерживает настройки

Наблюдатель выполняет применение только тогда, когда Wi-Fi-адаптер подключился к сети, отличной от сети последнего применения. Если после этого настройки изменились — руками, через NetSwitch или другой программой, — наблюдатель их не возвращает, а показывает расхождение в окне и в трее с кнопкой «Применить».

Поводы для проверки:

- уведомление о подключении Wi-Fi;
- выход из сна;
- запуск инструмента — если адаптер уже подключён к сети. Если это сеть последнего применения, применения нет, только проверка расхождения. Если сеть другая или последнего применения нет, применить сразу или только показать расхождение — настройка, по умолчанию «применить».

Подключение, которое запустило само переключение, наблюдатель пропускает: иначе профиль применился бы дважды.

## Considered Options

- **Удерживать настройки** — возвращать профиль при любом отличии. Тогда инструмент воевал бы с NetSwitch и с ручной правкой, например при проверке Ethernet-розетки или настройке роутера.
- **Без наблюдателя, только переключение по команде** — после сна и автоподключений Windows настройки молча не совпадали бы с сетью.

## Consequences

- Нужно помнить последнее применение между запусками инструмента (в журнале применений), иначе после перезагрузки «смену сети» нельзя отличить от повторного подключения к той же.
- Какие уведомления Windows присылает в каждом из поводов и с какими задержками, выясняет [разведочная сборка](../recon.md). По прогону 2026-10-26:
  - Подключение через системное меню и автоподключение после пропажи сети заканчиваются уведомлением ACM `connection_complete` с SSID и профилем сети Windows (Windows 11) — это повод «уведомление о подключении».
  - После сна S3 (Windows 10) подключение не переустанавливается: приходит только MSM `roaming_end` к тому же BSSID, без `connection_complete`. Событие выхода из сна (`PowerModeChanged Resume`) приходит уже после того, как адрес вернулся. Поэтому по выходу из сна наблюдатель сам читает текущую сеть, а не ждёт уведомления о подключении. Как это выглядит при Modern Standby (S0) на Windows 11 — не проверено.
  - Без доступа к местоположению (Windows 11) подписка на уведомления WLAN отказывает целиком, и имя сети тоже не прочитать: наблюдатель может только заметить смену адресов (`NetworkAddressChanged`), но не понять, в какой сети адаптер.
  - «Смена адресов» приходит 2–5 раз на один переход, а в событиях на отключение адреса ещё старые — проверку по ней нужно откладывать до успокоения.
  - Адрес по DHCP появлялся через 0,1–1 с после `connection_complete`, но каждый раз прежний; время получения нового адреса не измерено.
