# Проводные адаптеры не настраиваются

Инструмент меняет настройки IPv4 только на Wi-Fi-адаптере. Кабель подключают эпизодически — проверить Ethernet-розетку, настроить роутер, — а основной сетью остаётся Wi-Fi; для проводных адаптеров есть NetSwitch.

Прокси при этом общий для всего компьютера и всегда следует профилю текущей Wi-Fi-сети. Чтобы он не мешал работе по кабелю:

- в настройках прокси профиля есть флажок «Не через прокси для частных сетей» — он добавляет в исключения `10.*`, `192.168.*` и `172.16.*` … `172.31.*` (по записи на каждую вторую цифру: шаблоны исключений не умеют задавать диапазон);
- в меню трея есть пункт «Временно без прокси».

Если на проводном адаптере есть шлюз по умолчанию, Windows обычно отправляет интернет через него — метрика у проводного подключения меньше. Инструмент при этом ничего не меняет, а показывает заметный признак «Интернет сейчас идёт через Ethernet».

## Considered Options

- **Профили и для проводных адаптеров** — дублирование NetSwitch; оставлено в идеях на будущее.
- **Самому поднимать приоритет Wi-Fi через метрики** — неожиданное для человека изменение настроек проводного адаптера; можно добавить позже отдельной явной командой.

## Consequences

- Наблюдатель не реагирует на события проводных адаптеров.
- IPv6 не настраивается ни на каком адаптере и не показывается в окне; его состояние только записывается в отчёт.
- Определять, через какой адаптер идёт интернет, нужно по таблице маршрутов, а не по наличию шлюза; способ проверяет [разведочная сборка](../recon.md).
- По разведке 2026-10-26 на Windows 11 26H2 признак берётся только из `GetBestRoute2`. Утверждение выше, что при шлюзе на проводном адаптере Windows «обычно» отправляет интернет через него, не подтвердилось: USB-адаптер на 100 Мбит/с получил автоматическую метрику 35, как у Wi-Fi, и с метрикой маршрута 1 проиграл Wi-Fi-адаптеру — интернет остался на Wi-Fi. Автоматическая метрика Wi-Fi за день менялась от 25 до 55, так что исход сравнения заранее не предсказать. Решение — ничего не менять и показывать признак — от этого не меняется.
- Маршрут по умолчанию с ручным шлюзом остаётся в таблице и на отключённом проводном адаптере (с метрикой меньше, чем у Wi-Fi); `GetBestRoute2` его верно не выбирает, а перебор маршрутов по наименьшей метрике выбрал бы.
- Признак «Интернет сейчас идёт через Ethernet» горит, только когда `GetBestRoute2` выбрал физический проводной адаптер (#33). Через виртуальный адаптер обычно идёт VPN, часто поверх того же Wi-Fi, и называть это Ethernet неверно. Цена — признак молчит, когда кабель подключён через внешний коммутатор Hyper-V (виртуальный адаптер «vEthernet»); пока это допустимо.
