# Ручная проверка подключения на Windows 11

Этап 3 [плана](roadmap.md), [issue #30](https://github.com/AlexeyDesyatnik/WiFiControl/issues/30): до кода отката узнать, как Windows 11 сообщает об удачном и неудачном подключении. Переключение по [ADR 0004](adr/0004-ipv4-before-connect.md) считает неудачей только одно — «подключиться не удалось», и тогда откатывается. По плану этапа ([#29](https://github.com/AlexeyDesyatnik/WiFiControl/issues/29)) срок подключения — 30 с, а неудача определяется досрочно, по уведомлению. Оба правила предварительные.

Проверяет сценарий [`tools/connect-check/connect-check.ps1`](../tools/connect-check/connect-check.ps1). Он подключается через `netsh wlan` (`add profile` с XML, `connect`, `disconnect`) и пишет со временем состояние Wi-Fi-адаптера и события журнала WLAN-AutoConfig: 8001 — подключено, 8002 — не удалось, с кодом и текстом причины. Рядом запущена [разведочная сборка](recon.md): она пишет уведомления WLAN (ACM и MSM) с кодами причин. В обоих отчётах местное время с миллисекундами, поэтому их можно сопоставить. Разведочная сборка по-прежнему ничего не меняет.

Настройки IPv4 и прокси сценарий **не трогает**. Меняется только подключение, а ещё профиль сети Windows, если сценарий его создал. Такой профиль в конце удаляется.

## Что выясняем

- Через сколько секунд после команды Windows сообщает о неудаче, каким уведомлением и с каким кодом причины. Уведомления: ACM `connection_attempt_fail` и `connection_complete` с ненулевым кодом, MSM `disconnected`, событие 8002.
- Сообщает ли о неудаче вообще. Если ничего не приходит, откат держится только на сроке.
- Сколько длится удачное подключение, чтобы проверить срок 30 с.
- Сроки проверки после подключения: маршрут по умолчанию (план — ждать ~3 с), адрес (10 с), ping шлюза (3 попытки по 1 с), порт прокси (3 с).
- Подключается ли Windows сама к другой сети, пока адаптер отключён: после `netsh wlan disconnect` и после неудачи, пока шёл бы откат.

## Случаи

| Случай | `-Case` | Как устроить | Ожидается |
|---|---|---|---|
| Знакомая сеть | `Known` | Профиль сети Windows для `-Network` уже есть | 8001 |
| Новая WPA2-сеть с паролем | `New` | Профиля сети Windows нет, верный `-Password` | Профиль сети Windows создан, 8001 |
| Неверный пароль | `WrongPassword` | Профиля сети Windows нет, `-Password` неверный (по умолчанию `WiFiControl-wrong-1`) | 8002 или ничего |
| Скрытая сеть | `Hidden` | Точка доступа не показывает имя сети, профиля сети Windows нет, верный `-Password` | Профиль сети Windows с `nonBroadcast`, 8001 |
| Сеть вне зоны | `OutOfRange` | Точка доступа выключена. Берётся профиль сети Windows, а если его нет — создаётся | `netsh` отказывает сразу, или 8002, или ничего |

`OutOfRange` с `-NonBroadcast` создаёт профиль сети Windows с `nonBroadcast`, когда его ещё нет; в остальных случаях сценарий этот ключ отвергает. Такую сеть Windows ищет активно и не может узнать заранее, что сети нет. Это худший случай для срока.

На каждый случай сценарий делает шаги:

| Шаг | Что делает |
|---|---|
| 0 | Исходное состояние: адаптер подключён к прежней сети `-Previous`, список профилей сетей Windows (автоподключение, скрытая, защита), запущена ли разведочная сборка |
| 1 | `netsh wlan disconnect` и 15 с наблюдения: не подключится ли Windows сама (шаг 1 ADR 0004). Если подключится — записывается, проверка идёт дальше |
| 2 | Только если профиля сети Windows нет: `netsh wlan add profile` — WPA2-PSK, AES, автоподключение выключено, SSID в hex и именем ([ADR 0007](adr/0007-network-key-utf8-or-hex.md)) |
| 3 | `netsh wlan connect`, до 60 с ждать 8001 или 8002 этой сети |
| 4 | Удача: маршрут, адрес, ping шлюза, порт прокси (`-Proxy host:port`) и 45 с наблюдения за соединением. Неудача: сразу, без вопроса, 30 с наблюдения, как будто идёт откат |
| 5 | Возврат к прежней сети, как при откате: отключиться, удалить созданный профиль сети Windows, подключиться и засечь время |

Перед каждым шагом, кроме наблюдения после неудачи, сценарий объясняет, что сделает, и ждёт Enter. `q` прерывает, созданный профиль сети Windows при этом удаляется.

## Подготовка

- [ ] Ноутбук с Windows 11, учётная запись администратора.
- [ ] Разведочная сборка: самодостаточная сборка из [чек-листа разведки](recon-checklist.md), запуск от имени администратора. Её окно открыто на всё время проверки.
- [ ] Выключить VPN (AmneziaVPN).
- [ ] Прежняя сеть — `MichLycee`. Адаптер подключён к ней по DHCP.
- [ ] Сеть проверки — `HONOR 400`, её раздаёт телефон. Защита на телефоне — **WPA2-Personal**: сценарий создаёт профиль сети Windows WPA2-PSK, и с WPA3-only он не подключится.
- [ ] Для `New`, `WrongPassword` и `Hidden` профиля сети Windows `HONOR 400` быть не должно: чужой профиль сети Windows сценарий не перезаписывает. Удалить его, если он есть, и потом вернуть подключением из системного меню:

  ```powershell
  netsh wlan delete profile name="HONOR 400"
  ```

- [ ] Автоподключение. Первый круг — у всех сетей рядом выключено, как в [проверке записи](write-check.md). Для вопроса «подключается ли Windows сама» — второй круг, `WrongPassword` и `OutOfRange` с включённым автоподключением у `MichLycee`: «Параметры → Сеть и Интернет → Wi-Fi → Управление известными сетями → MichLycee → Подключаться автоматически в пределах досягаемости». Потом выключить обратно.

## Запуск

PowerShell **от имени администратора**, в папке репозитория:

```powershell
cd tools\connect-check
powershell -ExecutionPolicy Bypass -File .\connect-check.ps1 -Case Known
powershell -ExecutionPolicy Bypass -File .\connect-check.ps1 -Case New -Password 'пароль точки доступа'
powershell -ExecutionPolicy Bypass -File .\connect-check.ps1 -Case WrongPassword
powershell -ExecutionPolicy Bypass -File .\connect-check.ps1 -Case Hidden -Password 'пароль точки доступа'
powershell -ExecutionPolicy Bypass -File .\connect-check.ps1 -Case OutOfRange
powershell -ExecutionPolicy Bypass -File .\connect-check.ps1 -Case OutOfRange -NonBroadcast
```

Порядок удобный такой. Сначала `New`: после него профиль сети Windows удалён, сеть видна. Дальше `WrongPassword`. Потом `Hidden`: включить на телефоне «скрыть сеть», после проверки выключить. Затем `Known`: перед ним подключиться к `HONOR 400` из системного меню, чтобы появился профиль сети Windows, выключить у неё «Подключаться автоматически» (Windows включает его сама) и вернуться к `MichLycee`. Последним — `OutOfRange`: точку доступа выключить. Профиль сети Windows от `Known` при этом остаётся, а для `-NonBroadcast` его нужно удалить.

Другие имена: `-Network`, `-Previous`, `-Adapter`. Проверка порта прокси — `-Proxy 192.168.1.10:3128`. Сроки наблюдения: `-ConnectTimeout` (60), `-WatchAfterDisconnect` (15), `-WatchAfterFail` (30), `-WatchSeconds` (45).

Пароль в отчёт не попадает. На время команды `add profile` он лежит во временном файле XML, который сразу удаляется. В профиле сети Windows он хранится, как обычно, зашифрованным.

## Если что-то пошло не так

- **Windows сама подключилась к другой сети на шаге 1.** Это тоже ответ: он записан, и сценарий идёт дальше — подключение к сети проверки уведёт адаптер оттуда. Если это первый круг и сеть не `MichLycee`, выключить у неё автоподключение и запустить случай заново.
- **Прервали на середине.** Созданный профиль сети Windows удаляется и при `q`, и при Ctrl+C. Подключиться к `MichLycee` из системного меню.
- **Остался лишний профиль сети Windows.** Проверить список: `netsh wlan show profiles`. Удалить: `netsh wlan delete profile name="…"`.
