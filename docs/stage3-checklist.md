# Ручная приёмка этапа 3

Проверяем основную сборку WiFiControl по [этапу 3](https://github.com/AlexeyDesyatnik/WiFiControl/issues/29). Задачи #30–31 уже закрыты по итогам [ручной проверки подключения](connect-check.md#результаты-2026-10-29-windows-11-26h2) и прототипа. Здесь проверяем работу готовой программы, включая регрессионные сценарии #32–36.

- **Обязательно** — основные действия и сценарии, где ошибка может привести к потере связи, файла или записи на другой адаптер.
- **Желательно** — расширение покрытия, если доступны нужные сети, настройки или оборудование.
- **Если будет время** — редкие случаи. Их можно пропустить и оставить результат неизвестным.

Ставить отметку после проверки всех действий в пункте. Для неполной проверки записать, что именно прошло, что сломалось или каких условий не было. Если сокращённый прогон уже покрыл часть пункта, его результат можно перенести с указанием сборки и даты. После изменения соответствующего кода перепроверить этот сценарий на актуальной сборке.

## Подготовка

- Записать дату, версию Windows из `winver`, коммит сборки, локальные изменения при наличии и используемый Wi-Fi-адаптер. Для локальной сборки запустить `dotnet build WiFiControl.sln -c Release`, для автоматических проверок — `dotnet test WiFiControl.sln --filter "Category!=Machine"`.
- При закрытой программе сохранить копии `%APPDATA%\WiFiControl\WiFiControl.json` и `%LOCALAPPDATA%\WiFiControl\State.json`, если файлы существуют. Записать исходные настройки IPv4, системного и WinHTTP-прокси, включая автоопределение и PAC, разрешение доступа к местоположению и режимы автоподключения тестовых сетей.
- Подготовить рабочую сеть и отдельную тестовую сеть с DHCP, например точку доступа телефона с WPA2. Для нового подключения использовать отдельное имя сети, для которого в Windows ещё нет профиля. Эксперименты с ручным IPv4, прокси и паролем проводить в тестовой сети с возможностью вернуться в рабочую.
- Для проверок применения достаточно двух профилей: Автоматически и тестовый профиль с автоматическим адресом, заведомо рабочим ручным DNS для этой сети и выключенным прокси. Начать с профилем Автоматически по умолчанию. При сравнении смотреть в параметрах Windows и режим получения DNS, и его значение. Для режима автоподключения использовать `netsh wlan show profile name="<имя профиля сети Windows>"` без параметра вывода ключа.

## Обязательно

- [ ] **Главное окно и обновление (#32, #39).** Запустить программу, сверить сеть, IPv4, шлюз, DNS и прокси в блоке «Сейчас» с Windows. Текущая сеть идёт первой, остальные расположены по убыванию сигнала. Видны защита, сигнал и профиль, в том числе принадлежность к профилю по умолчанию. С одним Wi-Fi-адаптером выбора в окне нет. Переключиться между тестовыми сетями через Windows: блок «Сейчас» и список обновляются без перезапуска. Нажать «Обновить» и проверить, что появившаяся точка доступа видна.
- [ ] **Переключение на знакомую сеть (#35).** Назначить тестовой сети профиль с ручным DNS и подключиться к ней из программы. Сверить в окне порядок шагов: отключение, настройки IPv4, подключение, прокси, проверка. Пока идут шаги, второе переключение или применение недоступно. В Windows проверить сеть и DNS. У текущей сети вместо «Подключиться» доступно «Применить профиль…».
- [ ] **Новая сеть и откат после неверного пароля (#35–36).** Из рабочей сети начать подключение к новой тестовой WPA2-сети. Проверить, что слишком короткий пароль не даёт начать, а автоподключение изначально включено. Ввести допустимый по длине неверный пароль и дождаться результата. Должны вернуться прежняя сеть и её настройки IPv4, прокси остаётся прежним, временный профиль сети Windows исчезает. Затем повторить с верным паролем: Windows подключается и сохраняет профиль сети, в `WiFiControl.json` пароля нет.
- [ ] **Разовое применение и расхождение (#33–34).** Применить тестовый профиль через «Применить профиль…». Сеть остаётся подключённой, DNS меняется, привязка сохраняет прежнее значение, расхождение после успешного применения исчезает. Изменить DNS через Windows: окно показывает расхождение с последним применённым профилем. Нажать «Применить» у расхождения и проверить, что профиль восстановлен. Для профиля Автоматически адрес, полученный по DHCP, сам по себе не вызывает расхождения.
- [ ] **Режим автоподключения (#38).** У знакомой сети без привязки включить «Не подключаться автоматически», сверить ручной режим в Windows и перезапустить программу. Снять флажок и сверить автоматический режим. Изменить режим через системные параметры, обновить окно и проверить, что флажок совпал. У новой сети без профиля сети Windows флажка в списке нет. Если при переключении флажка на текущей сети повторится разрыв, записать время и состояние до и после.
- [ ] **Отказ в доступе к местоположению (#40).** Запретить классическим приложениям доступ к местоположению и проверить окно. Сеть неизвестна, доступные сведения IPv4 и прокси видны, команды подключения и применения недоступны. Обычное редактирование профилей доступно, обе команды для текущей сети недоступны. «Открыть параметры» ведёт на страницу расположения. После возврата разрешения «Проверить снова» возвращает сеть, список и команды без перезапуска.
- [ ] **Повреждённый файл профилей (#40).** При закрытой программе заменить содержимое тестового `WiFiControl.json` на `{`, открыть программу. Видна причина ошибки, «Открыть папку» ведёт к файлу. Подключение, применение, изменение привязок и редактор недоступны. Файл и сетевые настройки остаются прежними. Вернуть исправную копию, нажать «Перечитать», убедиться, что профили, привязки и команды снова доступны без перезапуска.
- [ ] **Привязка из строки (#41).** Выбрать тестовый профиль для текущей сети и ответить «Нет». После перезапуска привязка сохранена, DNS прежний. Выбрать «Без привязки», затем снова назначить тестовый профиль и подтвердить применение. Проверить DNS в Windows. Снять привязку с подтверждением и проверить возврат к профилю по умолчанию. Изменение привязки другой сети не вызывает вопроса о применении и не меняет параметры текущей.
- [ ] **Редактор, переименование и расхождение (#42).** Создать профиль, попробовать пустое и повторяющееся имя, неверный DNS или маску. Проверить понятные сообщения и возможность исправить ввод. Профиль Автоматически виден и защищён от изменения и удаления. Привязать профиль к сети, которой нет рядом, переименовать его и проверить, что привязка сохранилась. Затем применить профиль к тестовой сети и отредактировать его DNS: фактические настройки не меняются, окно показывает расхождение. После перезапуска проверить, что правка и привязка остались.
- [ ] **Профиль по умолчанию и удаление (#42).** Убедиться, что у текущей сети нет явной привязки. Назначить тестовый профиль по умолчанию, проверить предупреждение и вопрос о применении. Отказ сохраняет выбранный профиль по умолчанию без записи IPv4 и прокси. При изменении профиля по умолчанию для явно привязанной текущей сети вопрос не появляется. Попробовать отменить удаление используемого профиля и убедиться, что его привязки остались. Подтвердить удаление после проверки списка затронутых сетей. Их привязки исчезают, сети используют профиль по умолчанию. Если удалить сам профиль по умолчанию, им становится Автоматически.
- [ ] **Две команды для текущей сети (#43).** В сети с DHCP открыть «Профиль из текущих настроек…». Имя сети подставлено и редактируется, адрес и DNS в автоматическом режиме не превращаются в ручные. Изменить имя, сохранить профиль и проверить его после перезапуска. Затем выбрать его через «Привязать текущую сеть…». Если профиль текущей сети изменился, появляется тот же вопрос о применении, что в строке сети. После ответа «Нет» проверить сохранение привязки и прежний DNS. Повторить с тестовым профилем с ручным DNS и ответом «Да», сверить DNS в Windows.
- [ ] **Два Wi-Fi-адаптера, когда доступны (#39).** С двумя адаптерами выбрать второй, подключить его к тестовой сети и применить тестовый профиль. IPv4 меняется только на выбранном Wi-Fi-адаптере. Сверить также первый и, если есть, проводной адаптер. Перезапустить программу, убедиться, что выбор восстановился. Отключить выбранный адаптер, обновить окно, применить профиль на оставшемся. Вернуть второй адаптер и проверить, что сохранённый выбор восстановился. При отсутствии второго адаптера записать, что проверка записи на выбранный адаптер отложена.

## Желательно

- [ ] **Откат при пропаже знакомой сети (#35).** Сделать тестовую сеть недоступной после того, как она появилась в списке, и начать переключение, пока её строка ещё доступна. После сообщения об отказе или истечения срока прежняя сеть и IPv4 возвращаются, профиль знакомой сети Windows и прокси остаются прежними.
- [ ] **Пароль знакомой сети (#36).** Изменить пароль на тестовой точке доступа с существующим профилем сети Windows. После отказа воспользоваться «Ввести пароль заново». Убедиться, что переключение проходит, а повторное подключение через Windows работает с обновлённым паролем.
- [ ] **Скрытая сеть (#37).** На отдельной скрытой WPA2-сети без профиля сети Windows проверить ввод имени, защиты, пароля и флажок автоподключения. При неверном пароле временный профиль удаляется, прежняя сеть и IPv4 восстанавливаются. При верном пароле подключение проходит. После отключения и обновления проверить, что доступная скрытая сеть с профилем сети Windows отображается как знакомая. Если условий нет, записать причину отсрочки.
- [ ] **Смена режима и состояния адаптера (#39).** Выключить радио Wi-Fi, обновить окно и проверить сообщение «Wi-Fi выключен». Затем отдельно отключить сам адаптер или отсоединить единственный USB-адаптер, если это удобно. Проверить сообщение «Wi-Fi-адаптер не найден». После возврата адаптера список и команды снова работают.
- [ ] **Профиль из ручных настроек (#43).** В тестовой сети проверить три варианта команды «Профиль из текущих настроек…»: адрес по DHCP с ручным DNS, рабочий статический адрес с маской, шлюзом и DNS, ручной системный прокси с сервером и исключениями. Отдельно включить автоопределение и PAC и проверить предупреждение в форме. Сохранение профиля не меняет настройки Windows; в профиль попадают ручные настройки системного прокси, параметры PAC и автоопределения в нём отсутствуют.
- [ ] **Явная привязка к профилю по умолчанию (#41–43).** Привязать текущую сеть к тому же профилю, который действует для неё по умолчанию. Привязка сохраняется без вопроса о применении. Сменить профиль по умолчанию и проверить, что явно привязанная сеть сохраняет свой профиль, а сеть без привязки получает новое умолчание.
- [ ] **Предупреждения при рабочем подключении (#33–35).** В отдельной тестовой сети проверить один контролируемый сбой после подключения, например недоступный порт заданного тестового прокси. В ходе переключения видны предупреждение и причина, Wi-Fi остаётся подключённым, откат не начинается. Если есть проводная сеть с маршрутом в интернет, проверить соответствующий признак в блоке «Сейчас» и сохранность IPv4 проводного адаптера.
- [ ] **Клавиатура и узкое окно (#32, #42–43).** Уменьшить ширину главного окна, пройти до действий строки и редактора клавишей Tab. Проверить, что кнопки не перекрывают имя сети, меню можно открыть с клавиатуры, длинное имя профиля можно прочитать при выборе, а отмена редактора не сохраняет введённые данные. Закрытие главного окна завершает программу.

## Если будет время

- [ ] **Дополнительные типы защиты (#36–37).** На доступном оборудовании проверить открытую сеть, WPA3-Personal и смешанный WPA2/WPA3. В открытой сети пароль не запрашивается. Для WPA2 проверить допустимую фразу и, если точка доступа поддерживает, ключ из 64 шестнадцатеричных цифр. Для WPA3 проверить, что ключ такого формата не принимается. При наличии 802.1X или WEP проверить подсказку для новой сети и доступность подключения через уже существующий профиль сети Windows.
- [ ] **Повторяющиеся и необычные имена сетей (#32, #37, #41–43).** Если есть подходящие точки доступа, проверить одну строку для общего имени в нескольких диапазонах и выбор наибольшего сигнала. Для имени с байтами вне UTF-8 проверить отображение `hex:…` и сохранение привязки по этому ключу. Для вводимого вручную имени проверить границу 32 байта UTF-8 и различие имён по регистру.
- [ ] **Отказ без прежней сети или сбой возврата (#35).** Начать неудачное переключение, когда Wi-Fi включён, но адаптер ни к какой сети не подключён. IPv4 возвращается, шага обратного подключения нет. Если можно независимо выключить две тестовые сети, проверить неудачу возврата в прежнюю сеть: окно показывает и исходную ошибку, и ошибку отката.
- [ ] **Редкие признаки проблем и восстановление маршрута (#33–35).** На отдельной сети с управляемым DHCP и маршрутом проверить «Адрес не получен» и «Нет маршрута по умолчанию». Если Windows при подключении со статическим адресом теряет настроенный маршрут, проверить его восстановление в действующих настройках. Конфликт IPv4 воспроизводить только в изолированной сети с двумя тестовыми устройствами. Ожидаемые условия и сроки описаны в [ADR 0004](adr/0004-ipv4-before-connect.md).
- [ ] **Необычные состояния файлов (#39–40, #42).** При закрытой программе проверить запуск с отсутствующим файлом профилей и с файлом неизвестной версии. Отсутствие файла даёт начальное состояние, неизвестная версия блокирует запись с объяснением. С копией машинного файла проверить, что повреждённый `State.json` считается отсутствующим и корректно перезаписывается при следующем выборе адаптера. Если удаётся временно заблокировать запись профилей, проверить сообщение об ошибке, сохранность прежнего файла и возможность повторить сохранение.
- [ ] **Смена сети во время выбора (#41–43).** Открыть меню «Привязать текущую сеть…», переключить Windows на другую сеть и выбрать профиль из старого меню. Привязка из этого меню не сохраняется. Отдельно сменить сеть, пока открыт вопрос «Применить … сейчас?», и ответить «Да». Уже сохранённое изменение остаётся в файле, применение к новой сети не запускается.
- [ ] **Ещё одна версия Windows (#32–36).** Если есть доступ к Windows 10, повторить запуск, обновление списка и одно успешное переключение. Зафиксировать версию Windows и замеченные отличия в окне или ходе подключения.

## Завершение

- Вернуть исходные файлы и разрешение доступа к местоположению. Отдельно вернуть фактические настройки IPv4 и прокси, включая автоопределение и PAC, и исходные режимы автоподключения. Удалить только созданные для проверки профили сетей Windows, если они больше не нужны.
- Для сбоя записать номер задачи, сборку, действие, ожидаемый и фактический результат. Для разрыва соединения дополнительно записать время и состояние сети после сбоя. При необходимости приложить снимок окна или события WLAN за этот интервал.
- В подзадачах отмечать выполненные критерии с учётом ручных результатов и автоматических тестов. Оставлять открытыми критерии, которым нужна отложенная проверка. При публикации коммитов дождаться CI перед закрытием задач.
