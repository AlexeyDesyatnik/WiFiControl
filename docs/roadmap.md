## 1. Проверка записи на Windows 11 — сделано

Отдельный маленький шаг до основного кода: на Wi-Fi-адаптере проверить перенесённые из NetSwitch команды — статический адрес на отключённом адаптере и возврат к DHCP на отключённом адаптере ([ADR 0003](adr/0003-settings-written-as-in-netswitch.md)). На Windows 10 этот путь уже проверен. Инструкция и сценарий — [write-check.md](write-check.md).

Итоги — там же и в Consequences [ADR 0003](adr/0003-settings-written-as-in-netswitch.md) и [ADR 0004](adr/0004-ipv4-before-connect.md): запись работает как в NetSwitch, но после первого подключения со статическим адресом маршрут по умолчанию нужно проверять и при необходимости возвращать.

## 2. Ядро — сделано

Решения и границы этапа — в [issue #10](https://github.com/AlexeyDesyatnik/WiFiControl/issues/10), работа — в подзадачах #11–#17. Итог этапа — библиотека `WiFiControl.Core` с тестами. Окно и работа с Wi-Fi не входили в этап 2. В этапе 3 в ядро добавлена работа с Wi-Fi через `IWifiSystem`, а окно реализовано в отдельном проекте `WiFiControl`.

- Решение, проекты, сборка и тесты в GitHub Actions — по образцу NetSwitch.
- Перенос из NetSwitch: разбор и проверка адресов, настройки прокси, netsh и возврат к DHCP, запись прокси, применение по шагам с откатом, `INetworkSystem` с подменой в тестах, атомарная запись JSON.
- Новое в модели: сеть (по имени, [ADR 0007](adr/0007-network-key-utf8-or-hex.md)), привязка, профиль «Автоматически», профиль по умолчанию, флажок «Не через прокси для частных сетей».
- Хранилище `%APPDATA%\WiFiControl\WiFiControl.json`.

## 3. Окно и переключение — реализовано, идёт приёмка

Работы по [этапу 3](https://github.com/AlexeyDesyatnik/WiFiControl/issues/29) выполнены в подзадачах #30–43. Для приёмки актуальной сборки см. [чек-лист этапа 3](stage3-checklist.md).

Ручная проверка подключения выполнена 2026-10-29 на Windows 11 26H2. В [результатах](connect-check.md#результаты-2026-10-29-windows-11-26h2) записаны уведомления, коды и сроки, а также непроверенные случаи.

### Реализовано

- Главное окно со списком сетей, уровнем сигнала, защитой и назначенным профилем. В блоке «Сейчас» видны текущая сеть, адрес, шлюз, DNS, прокси и признаки проблем, в том числе расхождение.
- «Применить профиль…» для текущей сети без изменения привязки и «Применить» у расхождения.
- Переключение на знакомую сеть по [ADR 0004](adr/0004-ipv4-before-connect.md) с откатом при неудаче.
- Подключение к новой сети с вводом пароля и созданием профиля сети Windows, подключение к скрытой сети и команда «Ввести пароль заново».
- Флажок «Не подключаться автоматически» для знакомой сети. Режим хранится в профиле сети Windows.
- Если Windows не даёт доступ к местоположению, вместо списка сетей окно показывает объяснение и кнопку перехода в параметры Windows. Если файл профилей не прочитан, окно показывает причину и предлагает открыть папку и перечитать файл.
- Выбор Wi-Fi-адаптера с сохранением в машинном файле. При отсутствии выбранного адаптера инструмент работает с оставшимся.
- Выбор привязки в строке сети и в окне «Профили и привязки». Если меняется профиль текущей сети, инструмент спрашивает, применять ли его сразу.
- Редактор профилей и привязок, выбор профиля по умолчанию, удаление профиля с подтверждением и списком затронутых сетей. Команды «Профиль из текущих настроек» и «Привязать текущую сеть».

### Приёмка

Подзадачи #30–36 закрыты. В сокращённом прогоне на Windows 11 проверены запись режима автоподключения (#38), обработка повреждённого файла и запрета доступа к местоположению (#40), сохранение привязки и подтверждение применения (#41). При первом включении флажка автоподключения зафиксирован разрыв соединения, который не удалось повторить.

Проверки скрытой сети (#37) и двух Wi-Fi-адаптеров (#39) отложены до появления оборудования. Редактор и обе команды для текущей сети (#42–43) ждут ручной проверки. Результаты полной приёмки фиксируются по критериям соответствующих подзадач.

## 4. Трей, наблюдатель, автозапуск

- Значок и меню в трее: сети, переключение, «Отключиться», «Временно без прокси» (пока включено — пометка на значке и строка «Вернуть прокси» в окне).

- Команда «Запускать при входе» — создание и удаление задачи автозапуска ([ADR 0002](adr/0002-tray-app-elevated-via-task-scheduler.md)); один экземпляр программы.
- Уведомления Windows о результатах применения.

## Идеи на будущее

Не обязательства и не порядок работ.

- Импорт профилей из `NetSwitch.json`.
- Различать сети с одинаковым именем: по набору BSSID (известен до подключения) или по MAC-адресу шлюза (только после подключения, поэтому годится лишь наблюдателю). Профиль сети Windows всё равно один на имя, с одним паролем.
- Автонастройка прокси: сценарий (PAC) и автоопределение.
- Профили и для проводных адаптеров ([ADR 0006](adr/0006-wired-adapters-untouched.md)).
- Явная команда «Интернет через Wi-Fi» — поднять приоритет Wi-Fi метриками.
- Глобальная горячая клавиша для меню сетей.
- Командная строка: переключиться на сеть без окна.
- Перенос записи настроек в службу, если появится нужда работать без прав администратора у пользователя.
