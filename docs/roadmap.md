# План

Этапы идут по порядку: каждый следующий опирается на ответы предыдущего.

## 0. Разведочная сборка — сделано

Только чтение и запись событий, см. [recon.md](recon.md). Итог — заполненная таблица вопросов и поправки к ADR. Прогоны 2026-10-26; открытыми остались долгий сон и получение нового адреса по DHCP, Windows 10 отдельно не проверяется.

## 1. Проверка записи на Windows 11 — сделано

Отдельный маленький шаг до основного кода: на Wi-Fi-адаптере проверить перенесённые из NetSwitch команды — статический адрес на отключённом адаптере и возврат к DHCP на отключённом адаптере ([ADR 0003](adr/0003-settings-written-as-in-netswitch.md)). На Windows 10 этот путь уже проверен. Инструкция и сценарий — [write-check.md](write-check.md).

Итоги — там же и в Consequences [ADR 0003](adr/0003-settings-written-as-in-netswitch.md) и [ADR 0004](adr/0004-ipv4-before-connect.md): запись работает как в NetSwitch, но после первого подключения со статическим адресом маршрут по умолчанию нужно проверять и при необходимости возвращать.

## 2. Ядро

- Решение, проекты, сборка и тесты в GitHub Actions — по образцу NetSwitch.
- Перенос из NetSwitch: разбор и проверка адресов, настройки прокси, netsh и возврат к DHCP, запись прокси, применение по шагам с откатом, `INetworkSystem` с подменой в тестах, атомарная запись JSON.
- Новое в модели: сеть (по имени), привязка, профиль «Автоматически», профиль по умолчанию, флажок «Не через прокси для частных сетей».
- Хранилище `%APPDATA%\WiFiControl\WiFiControl.json`.

## 3. Окно и переключение

- Список сетей с сигналом, защитой и привязкой; текущее состояние: сеть, адрес, шлюз, DNS, прокси, признаки проблем.
- Переключение по порядку из [ADR 0004](adr/0004-ipv4-before-connect.md), с откатом при неудаче.
- Подключение к новой сети с вводом пароля (создание профиля сети Windows) и к скрытой сети.
- Выбор Wi-Fi-адаптера, если их несколько; выбор запоминается.
- Редактор профилей и привязок; «Профиль из текущих настроек», «Привязать текущую сеть», «Применить профиль…» для текущей сети.
- Удаление профиля, которым пользуются, — после подтверждения со списком затронутых сетей: их привязки удаляются, сети переходят на профиль по умолчанию. Предупреждение в редакторе, если профиль по умолчанию — не «Автоматически».
- Окно с объяснением и кнопкой, когда нет доступа к местоположению.

## 4. Трей, наблюдатель, автозапуск

- Значок и меню в трее: сети, переключение, «Отключиться», «Временно без прокси» (пока включено — пометка на значке и строка «Вернуть прокси» в окне).
- Наблюдатель по [ADR 0005](adr/0005-watcher-reacts-to-transitions.md), журнал применений.
- Команда «Запускать при входе» — создание и удаление задачи автозапуска ([ADR 0002](adr/0002-tray-app-elevated-via-task-scheduler.md)); один экземпляр программы.
- Уведомления Windows о результатах применения.

## 5. Выпуск

- Выбор поставки: framework-dependent или self-contained.
- Релизы по тегу `vX.Y.Z`, как в NetSwitch.
- Чек-лист ручной проверки.

## Идеи на будущее

Не обязательства и не порядок работ.

- Импорт профилей из `NetSwitch.json`.
- Различать сети с одинаковым именем: по набору BSSID (известен до подключения) или по MAC-адресу шлюза (только после подключения, поэтому годится лишь наблюдателю). Профиль сети Windows всё равно один на имя, с одним паролем.
- Автонастройка прокси: сценарий (PAC) и автоопределение.
- Профили и для проводных адаптеров ([ADR 0006](adr/0006-wired-adapters-untouched.md)).
- Явная команда «Интернет через Wi-Fi» — поднять приоритет Wi-Fi метриками.
- Глобальная горячая клавиша для меню сетей.
- Командная строка: переключиться на сеть без окна.
- Перенос записи настроек в службу, если появится нужда работать без прав администратора у пользователя.
