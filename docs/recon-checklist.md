# Чек-лист прогонов разведочной сборки

Рабочая форма [задания на разведку](recon.md): что сделать руками на каждой машине, чтобы ответить на вопросы из таблицы в конце задания. Сюда же собрано всё, что при разработке разведочной сборки (#2–#9) осталось непроверенным и ждёт прогонов.

Разведочная сборка ничего не меняет в системе. Всё, что меняется в этом чек-листе, — сеть, кабель, сон, доступ к местоположению, задача Планировщика, — меняет человек руками.

## Подготовка (дома, где есть .NET SDK)

- [ ] Собрать самодостаточную сборку — на машинах прогона ничего ставить не придётся:

  ```bash
  dotnet publish src/WiFiControl.Recon/WiFiControl.Recon.csproj -c Release -r win-x64 --self-contained
  ```

  Результат — папка `artifacts/publish/WiFiControl.Recon/release_win-x64/` (около 260 файлов, ~140 МБ). Для машины на ARM — `-r win-arm64`.
- [ ] Скопировать папку **целиком** на флешку. Через почту или облако — только архивом, и перед распаковкой в свойствах архива нажать «Разблокировать», иначе SmartScreen будет ругаться на неподписанный exe.
- [ ] Распечатать или открыть этот файл на телефоне.

## Каждая машина: перед первым запуском

- [ ] Записать выпуск и версию Windows: `winver` или «Параметры → Система → О системе».
  - **Ноутбук с Windows 10:** это решает судьбу [ADR 0001](adr/0001-csharp-net10-wpf.md). По [матрице поддержки .NET 10](https://github.com/dotnet/core/blob/main/release-notes/10.0/supported-os.md) (на 2026-09-28) из Windows 10 поддерживаются только 21H2, 1809 и 1607 в вариантах (E) и (IoT) — судя по набору версий, это Enterprise LTSC и IoT Enterprise LTSC. Обычной Windows 10 22H2 (Home, Pro) в матрице нет. Прогон делать всё равно: заодно станет видно, работает ли .NET 10 на этой системе на деле.
  - Если программа не запускается вовсе — записать текст ошибки и, если есть, событие в «Просмотре событий → Журналы Windows → Приложение».
- [ ] Положить папку в постоянное место, например `C:\Recon\`. Отчёты сохраняются в `Отчёты` рядом с exe.
- [ ] Проверить, что есть: Wi-Fi-адаптер, две знакомые сети (например, рабочая и точка доступа с телефона), кабель в сеть со шлюзом.

## Запуски

| Машина | А. Вручную, с UAC | Б. Из Планировщика | В. Без доступа к местоположению |
|---|---|---|---|
| Ноутбук, Windows 10 | [ ] | [ ] | — |
| Windows 11 24H2+ | [ ] | [ ] | [ ] |

В каждом запуске пройти сценарии ниже (в запуске В — только сценарий 6) и **сохранить отчёт перед закрытием программы**: лента событий живёт только пока окно открыто. После сохранения дописать к имени файла букву запуска, например `LAPTOP-7_2026-10-27_10-15_А.txt`.

### Как создать задачу для запуска Б

1. «Планировщик заданий» → «Создать задачу…» (не «простую»).
2. «Общие»: имя `WiFiControl Recon`; «Выполнять только для пользователей, вошедших в систему»; отметить «Выполнить с наивысшими правами».
3. «Триггеры» → «Создать»: «При входе в систему», для своего пользователя.
4. «Действия» → «Создать»: «Запуск программы», путь к `WiFiControl.Recon.exe`; «Рабочая папка» — папка с exe.
5. «Условия»: снять «Запускать только при питании от электросети».
6. Выйти из системы и войти снова — окно должно появиться **без запроса UAC**. Ручной запуск задачи кнопкой «Выполнить» допустим как запасной вариант, но в отчёте это отметить.
7. После прогонов задачу удалить.

## Сценарии

Время ручных действий записывать на бумаге или в телефоне (например, «10:42:15 — выключил точку доступа»): по ним потом сверяется лента.

### 1. Запуск и чтение

- [ ] Окно открылось; при чтении и ожидании сканирования (до 10 с) оно не подвисает, кнопки и прокрутка работают.
- [ ] Лента событий внизу окна заполняется на лету — хотя бы `WLAN ACM scan_complete (7)` от первого чтения.
- [ ] Сделать **скриншот окна** — ответ на вопрос «как выглядит Fluent-тема WPF».
- [ ] Пролистать отчёт и отметить, где есть строки `ОШИБКА` и с какими кодами. По разделам:
  - **Система:** «Из Планировщика» — «нет» в запуске А и «да» в запуске Б; основание выглядит правдоподобно.
  - **Wi-Fi-адаптеры, Текущее подключение:** данные совпадают с `netsh wlan show interfaces`.
  - **Видимые сети:** сколько ждали уведомления о конце сканирования; не вышло ли время.
  - **Профили сетей Windows:** режим подключения совпадает с галочкой «Подключаться автоматически» у этих сетей.
  - **Настройки IPv4, Системный прокси, WinHTTP-прокси:** на Windows 10 они проверяются впервые — сверить с `ipconfig /all`, настройками прокси Windows и `netsh winhttp show proxy`.
  - **Доступ к местоположению:** что записано для пользователя и компьютера.

### 2. Переключение на другую сеть через системное меню Windows

- [ ] Переключиться на вторую знакомую сеть, подождать полминуты, переключиться обратно.
- [ ] В ленте: какие уведомления ACM и MSM пришли и в каком порядке.
- [ ] У уведомлений о подключении и отключении (`connection_start`, `connection_complete`, `disconnected`, MSM `associated`, `connected`) видны правильные SSID, профиль сети Windows и BSSID. Проверка разбора данных уведомлений, которую нельзя было сделать без смены сети.
- [ ] Сколько секунд от `connection_complete` до «Смены адресов» с адресом по DHCP (не 169.254.x.x).

### 3. Выход из зоны сети и возвращение

Удобнее всего — точкой доступа на телефоне.

- [ ] Подключиться к точке доступа телефона, выключить её, подождать минуту, включить.
- [ ] В ленте: что пришло при пропаже сети и при автоподключении после её возвращения; сколько до адреса по DHCP.

### 4. Сон на несколько минут и выход из сна

- [ ] Отправить в сон (меню «Пуск» или крышка), подождать 3–5 минут, разбудить.
- [ ] В ленте есть «Питание: Suspend» и «Питание: Resume». На ноутбуках с современным режимом ожидания их может не быть — тогда записать это (проверить режим можно командой `powercfg /a`: строка «Standby (S0 Low Power Idle)»).
- [ ] Какие уведомления пришли при автоподключении после сна; сколько от выхода из сна до адреса по DHCP.
- [ ] После сна нажать «Прочитать заново» — данные свежие, ошибок нет.

### 5. Кабель в сеть со шлюзом

- [ ] Подключить кабель, подождать полминуты, «Прочитать заново».
- [ ] В разделе «Маршрут в интернет» выбран проводной адаптер; сравнить метрики.
- [ ] Отключить кабель, «Прочитать заново» — маршрут вернулся на Wi-Fi.
- [ ] В ленте: «Смена адресов» при подключении и отключении кабеля.
- [ ] Если включён VPN — отметить: в выбранном маршруте может быть сеть VPN, а не 0.0.0.0/0.

### 6. Без доступа к местоположению (только Windows 11, запуск В)

- [ ] До выключения записать из раздела «Доступ к местоположению» значения для пользователя и `GlobalPromptShown`.
- [ ] Выключить «Параметры → Конфиденциальность и защита → Расположение → Разрешить классическим приложениям доступ к местоположению».
- [ ] Перезапустить программу. Какие разделы отказали и с какими кодами: «Текущее подключение», «Видимые сети», «Профили сетей Windows», «Случайный MAC-адрес». Ожидается код 5, но важен фактический.
- [ ] Пройти сценарии 3–4 и посмотреть, что в ленте: приходят ли уведомления WLAN и есть ли в них SSID.
- [ ] Сохранить отчёт.
- [ ] Включить доступ обратно, перезапустить программу. Появился ли запрос Windows при первом обращении? Как изменились `GlobalPromptShown` и запись программы в «Классических приложениях»?
- [ ] Сохранить ещё один отчёт.

## Если будет время: случайный MAC-адрес

Это меняет настройки Wi-Fi Windows (руками, не программой) — только там, где это допустимо, и с возвратом обратно.

- [ ] Включить «Параметры → Сеть и Интернет → Wi-Fi → Случайные аппаратные адреса», переподключиться, «Прочитать заново». Что в разделе «Случайный MAC-адрес»: отличается ли текущий адрес от постоянного, выставлен ли бит, появился ли `RandomMacState` в реестре, что в XML профиля.
- [ ] Выключить общий переключатель, в свойствах текущей сети выбрать «Случайные аппаратные адреса: Вкл» (и затем «Ежедневно», если есть), переподключиться, «Прочитать заново».
- [ ] Вернуть настройки как были.

## Что привезти

- [ ] Все отчёты из папки `Отчёты` с каждой машины, с буквой запуска в имени.
- [ ] Выпуск и версию Windows каждой машины (из `winver`).
- [ ] Заметки со временем ручных действий.
- [ ] Скриншоты окна.
